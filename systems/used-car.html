MAIN FEATURES

買取から販売・納車後までを支える、
10の主要機能。

査定受付だけに限定せず、買取車の商品化、販売在庫、商談、契約、納車、アフターまでを顧客と車両の流れとして扱います。

SELL

買取・下取り査定受付

お客様が店頭・出張・写真査定を選び、車両情報、希望日時、写真をLINE側から送信します。

360

顧客・所有車360°管理

店舗が顧客と所有車、査定、商談、契約、履歴を関連付け、重複候補を確認しながら編集します。

BUY

査定進行・買取契約

査定額、次回対応、検討・合意、書類、引取までを追跡し、合意後の買取契約作成へつなぎます。

STOCK

商品化・販売在庫変換

買取車両を入庫・商品化タスクへ移し、準備完了後に販売在庫として管理します。

WEB

公開在庫・車両詳細

公開条件と掲載準備を確認し、写真、支払総額、状態、詳細条件をお客様向け在庫画面へ掲載します。

DEAL

試乗・商談・販売契約

来店・試乗・購入・下取り相談、見積、ローン相談、次回対応、失注理由、販売契約を管理します。

GOAL

必要書類・入金・納車

契約後の必要書類、入金、登録・納車準備、未完了タスクを確認し、完了条件を満たして納車へ進めます。

CARE

アフター・整備履歴

納車後の点検、車検、オイル交換などの予定と履歴を確認し、次回案内や代替提案へつなぎます。

LINE

LINE連絡・履歴

査定結果、書類、納車、点検案内のテンプレート、送信予定、履歴を管理します。自動送信は標準でOFFです。

DATA

入出金・帳票・分析・CSV

未収・入金・支払、帳票、粗利・在庫回転・成約率、担当実績を確認し、CSVは事前検査後に確定します。

FROM FIRST CONTACT TO AFTERCARE

最初の相談から納車後まで、
6つの流れ。

売却と購入を別々の顧客情報にせず、下取りを伴う買い替えも含めて、同じお客様・車両情報から次の業務へ引き継ぎます。

01

LINEから入口を選ぶ

お客様が「車を売りたい」「車を買いたい」「マイページ」から目的を選びます。

02

査定・在庫相談を受付

車両情報・写真・希望日時、または在庫・試乗・購入相談を受け付けます。

03

PC・iPadで現場対応

スタッフが来店、査定、商談、次回対応を確認し、その場で進行を更新します。

04

買取・商品化・販売へ

買取成立車は契約・引取・入庫を経て商品化し、公開準備後に販売在庫へ移します。

05

契約・書類・納車準備

販売契約、必要書類、入金、登録、車両準備、納車予定を店舗とお客様で確認します。

06

納車・アフターへ継続

納車完了後にフォロー予定を作成し、点検・車検・整備履歴、次回提案へつなぎます。

SAFE OPERATION

営業デモから本番導入まで、
安全確認を前提に。

本番環境へ自動で切り替えず、公開範囲、管理権限、データ移行、外部連携の状態を確認してから運用を開始します。

01 / SEPARATE

デモと本番を分離

公開デモは架空データを使用し、本番は契約店舗ごとのGitHub、Worker、データベースとして分離します。

02 / GUARD

公開・管理者ガード

公開在庫と非公開の査定写真・管理情報を分け、管理画面は認証と権限を前提に取り扱います。

03 / DATA

重複・移行前検査

電話番号の表記を整えて照合し、重複候補を確認します。CSV移行はプレビュー・検査後に確定します。

04 / MANUAL

自動実行を標準でOFF

LINE自動送信、銀行自動連携、CSV自動確定、本番環境の自動変更は標準でOFFとし、人の確認を残します。

置き換えない業務：実車査定・整備・車検、名義変更などの法定手続き、ローン審査、決済・銀行処理そのものは、店舗や外部サービスで行います。帳票PDFはブラウザの印刷・PDF保存を利用する構成です。

FAQ

中古車買取・販売店向けDPROシステムの
よくある質問。

どのくらいの規模の中古車店を想定していま⁠す⁠か⁠。

買取・下取りと中古車販売を一つの店舗または少人数のチームで行い、顧客・車両・査定・在庫・商談・納車を同じ流れで管理したい事業者を主な対象としています。大規模チェーンや基幹システム全体の置き換えは個別確認です。

スマートフォンやiPadでも使えま⁠す⁠か⁠。

お客様向け入口とマイページはスマートフォン、現場スタッフ向け画面はiPad・タブレット、店舗総合管理はPCを中心に設計しています。ブラウザから利用します。

LINEを利用しないお客様も管理で⁠き⁠ま⁠す⁠か⁠。

店舗側のPC・iPadでは、顧客・車両・査定・商談を管理できます。LINE連携していないお客様への連絡方法や受付手順は、現在の電話・店頭対応と併用して設計します。

今使っている販売管理や整⁠備⁠シ⁠ス⁠テ⁠ムと併用で⁠き⁠ま⁠す⁠か⁠。

併用を前提に整理できます。DPROはお客様とのLINE受付、査定・在庫・商談・契約・納車・アフターの進行共有を中心とし、既存の会計・整備・車検・登録業務を自動的に置き換えるものではありません。

在庫を自動で公開しても大丈夫で⁠す⁠か⁠。

公開準備と公開条件を確認してから掲載する設計です。非公開の査定写真を自動公開する設定はOFFで、公開前の確認を残します。

公開デモに本物のお客様情報は入っていま⁠す⁠か⁠。

入りません。公開デモは架空データを使用します。本番環境は契約店舗ごとに分離し、公開デモとは別のGitHub、Worker、データベースで運用します。
