FROM RESERVATION TO REVISIT

患者様の予約から、
次回来院の準備まで。

予約受付だけを切り出さず、来院当日の院内運用と、施術後の継続案内までを一つの流れとして扱います。

01

LINEから予約

メニュー、担当、症状・要望、30分単位の希望日時を選択します。

02

予約内容を確認

会員ホームで次の予約を確認し、必要に応じて変更・キャンセルします。

03

来院受付

受付iPadまたはPCで来院操作し、予約から来院へ状態を進めます。

04

施術を開始

スタッフスマホまたは管理画面で担当患者を確認し、施術中へ更新します。

05

施術完了・履歴

完了へ進め、担当、メニュー、来院履歴、回数券などを患者単位で確認します。

06

次回来院・フォロー

次回来院目安やフォロー対象を整理し、必要な患者様へ案内する準備をします。

LINEを使わない患者様の予約も、受付PC・iPadから電話・窓口受付として同じ当日運用へ追加できます。電話番号はハイフン、空白、全角、国番号表記を正規化して患者検索へ利用する設計です。

SAFE OPERATION

公開デモから本番導入まで、
認証と環境分離を前提に。

管理コードを公開ファイルへ直書きせず、管理操作は専用ヘッダーで認証する構成です。デモ専用リセットと安全確認機能も分けています。

01 / SEPARATE

公開デモと本番を分離

公開デモは架空データを使用し、本番は契約店舗ごとの専用環境として構成します。

02 / AUTH

管理コードを公開ファイルに埋め込まない

管理用の認証情報は公開設定ファイルへ直書きせず、管理画面で入力して利用する設計です。

03 / API & DB

Worker API・データベースへ保存

患者、予約、進捗、履歴、回数券、フォロー情報をAPI経由で保存・再取得します。

04 / CHECK

安全確認とデモ専用リセット

不正な管理認証の拒否、デモ環境だけでのリセット、公開前の接続・保存確認を前提にしています。

  • 管理コードをURLや公式紹介ページへ掲載しない
  • 管理操作は公開画面と権限を分ける
  • デモリセットはデモ環境に限定する
  • 初期表示で大量の履歴や画像を取得しない

FAQ

整骨院・整体向けDPROシステムの
よくある質問。

どのような院を対象にしていま⁠す⁠か⁠。

整骨院、接骨院、整体院、鍼灸院など、予約と来院受付、施術進捗、患者履歴、回数券、再来院案内を整理したい小規模・中小規模の院を主な対象としています。詳細な同時予約数や運用条件は、現在の予約方法を確認して個別に設定します。

スマートフォンやiPadでも使えま⁠す⁠か⁠。

患者様はスマートフォンの予約・会員ホーム、受付はiPad・タブレット、施術スタッフはスマートフォン、院長・管理者はPC管理画面を利用する構成です。

LINEを使わない患者様の予約も扱えま⁠す⁠か⁠。

はい。電話・窓口で受け付けた予約も、受付PC・iPadから同じ当日運用へ追加できます。患者検索では電話番号表記を正規化して照合する設計です。

今使っている予約表や施術録と併用で⁠き⁠ま⁠す⁠か⁠。

併用できます。本システムは主に予約、来院受付、院内進捗、患者情報確認、回数券、再来院フォローを対象とし、施術録・電子カルテ・レセプト・決済そのものを置き換えるものではありません。

公開デモと本番環境は同じで⁠す⁠か⁠。

同じではありません。公開デモは架空データを使用し、本番は契約店舗専用の環境として分離します。管理用の認証情報は公式紹介ページや公開設定ファイルへ掲載しません。
